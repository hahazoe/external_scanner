## 项目通读分析（external_scanner / Cocos2d DebugView）

对全仓做了首次架构分析，未修改任何源码。

**定位**：Windows 32 位、Cocos2d-x + Lua 5.1 进程的外部调试与逐帧性能分析工具，
viewer（debugview.exe）与目标进程内注入 DLL（inject_exec.dll）通过命名共享内存通信。

**规模**：一方代码约 11k 行
- injection/ 约 5.4k（lua_profiler.c 1340、injected_runtime.c 1433、luac_dump.c 819、injector.c 795、lua_vm_scan.c 236、telemetry_writer.c 186、lua_api_hooks.c 219）
- debugview/ 约 4.4k（main.cpp 2180、debug_list.cpp 608、recording_io.cpp 423、telemetry_client.cpp 397、frame_preview.cpp 335）
- tests/ 约 1.0k，common/profiler_ipc.h 255

**关键约定**
- IPC：`Local\CocosDebugProfiler_v8_<pid>`，magic 0x42444343（CCDB），version 8；magic/version 不匹配直接拒连。
- 录制格式 `.cocosdbg`，magic `CCDBREC1`，version 5，旧版本拒读。
- 帧上限：方法 2048 / 行样本 128 / C++ hook 12 / 帧环 256 / 事件环 32768 / 线程 1024 / 栈深 256。
- 目标符号解析顺序：先 `libcocos2d.dll`，再目标主 exe；必选 `cc.Director:drawScene`，
  `cc.Renderer:render` 与 `cc.Scene:render` 可选。
- 远程 Lua 不在 C++ hook 里 pcall，由 Cocos Scheduler 在安全 Lua 上下文中 drain。
- 二次注入被显式拒绝：需重启目标进程。
- 构建：`build.bat`（32 位 MinGW，Lua 源码需 `../Lua_5_1_4/src`），产物 build/debugview.exe。

**观察到的可改进点**（已反馈给用户）
1. 存在三份独立 x86 指令长度解码器（injected_runtime.c / lua_api_hooks.c / luac_dump.c），
   覆盖面不一致：后两者对 0x0F 前缀直接返回 0，SSE 序言函数会 hook 失败。
2. `lp_touch_local()` 对每线程 512 个累加器做线性扫描，hook 热路径 O(n)。
3. 名字缓存按 `ar->source` / `ar->name` 裸指针做 key，字符串对象回收后地址复用可能误命中。
4. 打补丁时未挂起其他线程，属 inline hook 常规风险（未见规避措施）。
5. build/ 与 temp/ 存留历史产物：`lua_<tick>.dll` 1665 个、`yszt_capture_*.yszt`（旧格式名）、
   `cocos_debug_perf_*.json`；.gitignore 已忽略 build/ temp/，但未被纳入版本控制。

**目标样本**：`sealapp.exe`，已 dump 到 `build/generated/luac_dump/sealapp/`（1500+ 个 .lua）。

**环境注意**：本机 Bash 工具不可用（`dirname`/`ls` 缺失），PowerShell stdout 不回传，
用 Read/Glob/Grep 完成全部探查。

## 优化点清单（第二轮，读全 lua_profiler.c / injected_runtime.c 后确认）

P0 正确性：
1. 三份 x86 解码器不一致，lua_api_hooks.c / luac_dump.c 遇 0x0F 前缀返回 0（SSE 序言 hook 失败）。
2. LpNameCache 裸指针 key，地址复用可误命中（lua_profiler.c:278-337）。
3. patch 写入非原子（先 E9 后 4 字节偏移），其他线程可能取到撕裂指令。
4. remove_one_cpp_hook 死代码，SHUTDOWN 不卸载 → 二次注入必须重启。

P1 性能（目标进程内）：
5. lp_touch_local 每次 CALL/RET 线性扫 512 累加器（lua_profiler.c:394）。
6. lp_merge_method 帧末 O(T×512×2048) 平方合并（lua_profiler.c:785）。
7. lp_union_thread_intervals 帧末 O(intervals×threads)（lua_profiler.c:736）。
8. lp_profile_hook 每事件全局锁+线程锁两把（lua_profiler.c:589-717）。
9. luac_dump hook_loadfile 在游戏线程同步读整个文件（luac_dump.c:739）。

P1 viewer：
10. FrameSnapshot 每方法 std::string，10000 帧×2048 方法最坏 ~20M 字符串（telemetry_client.h:11-27）。
11. pending_trace_events 每事件倒扫 10000 帧历史（main.cpp:490-512）。

P2 架构：
12. main.cpp 2180 行单文件；四套 trampoline 安装代码重复。
13. x86 解码器无单测；runtime_ab_test 不在默认构建。

用户选择全部实施（P0 三件套 + P1 热路径 + viewer 内存）。
